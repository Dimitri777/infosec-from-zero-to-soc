# Path from Zero to IS Department and SOC

Realistic roadmap for growing an Information Security function.

---

## 0–3 Months — "Firefighting Stage"

**Goal:** Stop the most dangerous gaps and create minimum viable security function.

Typical activities:
- One person (or very small team) focuses on critical risks
- Basic policies and procedures appear
- Incident response is organized (mostly manual)
- First assessment of current security level is completed

**Outcome:** Organization is no longer completely blind and reactive only.

---

## 3–9 Months — Forming the Function

**Goal:** Turn ad-hoc actions into repeatable processes.

Typical activities:
- Clear ownership of Information Security appears
- Basic technical controls are implemented (EPP, vulnerability scanners, central logging)
- Regular vulnerability and access reviews start
- Employees receive minimum security awareness
- First metrics and reporting to management are introduced

**Outcome:** Information Security becomes a recognizable function, not just "someone who sometimes helps".

---

## 9–18 Months — Information Security Department

**Goal:** Build a real team and more mature processes.

Typical activities:
- Dedicated roles appear (analyst, engineer, compliance/personal data specialist)
- Processes become more formal (risk management, secure change management, vendor management)
- Centralized event collection improves (early SIEM or equivalent)
- Regular internal checks and continuous improvement cycle start

**Outcome:** The company has a working Information Security department capable of handling day-to-day security operations.

---

## 18–36 Months — Moving Toward SOC

**Goal:** Create operational capability for continuous monitoring and response.

SOC characteristics:
- Continuous (or near-continuous) monitoring of security events
- Investigation and coordination of incident response
- Playbooks and accumulated expertise
- Clear escalation paths to IT and business

What is usually required before building a SOC:
- Sufficient log sources from critical systems
- Appropriate tools (SIEM, EDR, ticketing)
- People who can analyze, not only watch dashboards
- Defined processes for detection, triage, investigation, and response
- Management understanding of cost and expected value

**Note:** Many mid-size organizations stop at a strong IS department + external SOC/MDR service instead of building a full 24/7 internal SOC.

---

## Key Message for Interviews

"I would not start with a full SOC.  
First we need a working Information Security function that understands the business, closes critical gaps, and runs basic processes.  
SOC is a later stage of maturity that becomes effective only when data, processes, and people are already in place."
